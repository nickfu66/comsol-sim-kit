# 代码说明

## 执行顺序

1. 在任务书和 quality_spec.json 中冻结目标与判据。
2. 在 case_spec.py 中填写 RESET_PARAMS 和 CASES。
3. 在 model_common.py 中实现 build_model，先应用 RESET_PARAMS 再应用当前工况参数，返回 model、mesh、study 和 probes。
4. quality_spec 的判据 ID 与聚合输出一致，统一使用 <工况>.<探针ID>，例如 C0.K1。
5. 先运行 preflight 与 lint，再运行 run_cases.py；只有全部声明工况通过当前指纹和双模型校验，driver 才生成带完整 provenance 的 values.json 并更新 results_manifest.json。
6. 收尾运行 gate --bundle --emit，默认读取聚合后的 values.json；缺失、陈旧或中断结果不能通过。

## 文件

- paths.py：统一产物路径，不在其他脚本硬编码输出目录。
- case_spec.py：不可变工况、参数复位表、执行依赖清单和唯一指纹实现。
- model_common.py：本案例唯一的建模实现位置；新增 helper 必须加入 DEPENDENCY_FILES。
- run_case_one.py：单工况参数复位、按工况双模型保存、求解、模型哈希和结果落盘。
- run_cases.py：顺序执行工况，按参数、环境、脚本与模型指纹跳过有效旧结果，并自动聚合。
- 探针/：一次性验证脚本，收尾保留并说明结论。
- 日志/：运行日志与需要留存的旧结果。
